# Migrating to 1.0.0

impaktfull_ui renames public APIs through deprecation, not by breaking them:

1. A release adds the new name and keeps the old one as a `@Deprecated` alias. Your code keeps compiling; the analyzer shows a deprecation warning that names the replacement.
2. The old names keep working for every 0.x release.
3. 1.0.0 removes all of them at once.

This guide lists every deprecated API that 1.0.0 removes. The [CHANGELOG](../../CHANGELOG.md) lists the release each deprecation shipped in, under **Deprecations**.

## Coming from 0.79.x or older: upgrade to 0.80.0 first

**Every rename in this guide shipped in 0.80.0**, which is the only release where the old and the new names both exist. That is what makes the automatic migration below possible.

1. Set `impaktfull_ui: 0.80.0` in `pubspec.yaml` (the exact version, not a range) and run `flutter pub get`.
2. Run `dart fix --dry-run`, then `dart fix --apply`.
3. Run `flutter analyze` and handle what is left by hand: every remaining deprecation warning names its replacement, and the ones `dart fix` cannot do are listed below.
4. Only then move to a newer version.

Skipping 0.80.0 means upgrading straight into a release where the old names are gone, so your code stops compiling and `dart fix` has nothing to match.

## Migrate automatically

Every rename below ships with a data-driven fix (`lib/fix_data.yaml`), so `dart fix` rewrites your code for you:

```bash
dart fix --dry-run   # show what would change
dart fix --apply     # change it
```

Do this on any 0.x release before upgrading to 1.0.0. After 1.0.0 the old names no longer exist, so there is nothing left for `dart fix` to match.

## Global theme and locale

The top-level `theme` and `locale` getters were global variables, set by `ImpaktfullUiApp`. A global can not follow a theme override lower in the tree, and a widget that reads it does not rebuild when the theme changes. They are deprecated: read the theme and the locale from the widget tree instead.

| Deprecated | Replacement |
| --- | --- |
| `theme` | `ImpaktfullUiTheme.of(context)` |
| `locale` | `Localizations.localeOf(context)` |
| `setImpaktfullUiTheme(theme)` | `ImpaktfullUiApp(impaktfullUiTheme: theme)` |
| `setImpaktfullUiLocale(locale)` | `ImpaktfullUiApp(locale: locale)` |
| `setImpaktfullUiTestTheme(theme)` | Pump the widget under test in an `ImpaktfullUiApp(impaktfullUiTheme: theme)` |

`dart fix` can not migrate these: the replacement needs a `BuildContext`. Replace them by hand:

```dart
// Before
@override
Widget build(BuildContext context) {
  return Text('Hello', style: theme.textStyles.onCanvas.text.small);
}

// After
@override
Widget build(BuildContext context) {
  final theme = ImpaktfullUiTheme.of(context);
  return Text('Hello', style: theme.textStyles.onCanvas.text.small);
}
```

To find every use, remove `theme` from the import and let the analyzer list the places that no longer compile:

```dart
import 'package:impaktfull_ui/impaktfull_ui.dart' hide theme, locale;
```

In code without a `BuildContext` (a service, a static helper), pass the theme (or the value you need from it) as a parameter, or use `ImpaktfullUiTheme.getDefault()` if you never change the theme.

Until 1.0.0 `ImpaktfullUiApp` keeps setting the global theme and locale, so the deprecated getters keep returning what they returned before. The components and building blocks of this package no longer read them.

## Extensions no longer exported

The package exported extensions without the `ImpaktfullUi` prefix on types of Flutter and Dart. They added members such as `format`, `isSameDay`, `tomorrow`, `bold` and `start` to every `DateTime`, `TextStyle` and `EdgeInsetsGeometry` of your app, where they clash with extensions of your own or of other packages. 1.0.0 no longer exports them.

| Deprecated | Migration |
| --- | --- |
| `ResponsiveExtension` on `BuildContext` (`context.isSmallScreenOrBigger`, ...) | The static helpers of `ImpaktfullUiResponsiveLayout`: `context.isSmallScreenOrBigger` becomes `ImpaktfullUiResponsiveLayout.isSmallOrBigger(context)`, `context.isMediumScreenOrSmaller` becomes `ImpaktfullUiResponsiveLayout.isMediumOrSmaller(context)`, and so on |
| `TextStyleExtension` (`light`, `medium`, `semiBold`, `bold`, `withOpacity`) | `style.copyWith(fontWeight: FontWeight.w300)` (`w500`, `w600`, `w700`), `style.copyWith(color: style.color?.withValues(alpha: opacity))` |
| `DateTimeExtensions` (`format`, `isSameDay`, `tomorrow`, `startOfTheDay`, ...) | Copy it into your app |
| `getDayForMonthWithFallback` | Copy it into your app |
| `BorderRadiusGeometryExtension` (`topStart`, ..., `value`, `copyWith`) | Copy it into your app, or use `BorderRadiusGeometry.resolve(textDirection)` |
| `EdgeInsetsGeometryExtension` (`start`, `end`, `top`, `bottom`) | Copy it into your app, or use `EdgeInsetsGeometry.resolve(textDirection)` |
| `ThemeDataExtension` (`removeUnwantedBehavior`) | Copy it into your app. `ImpaktfullUiApp` keeps applying it to the `ThemeData` you pass |

The extensions and each of their members are deprecated, so the analyzer points at every use (an extension member is only reported when the member itself is deprecated). They keep working until 1.0.0.

`dart fix` can not migrate these: there is no replacement with the same shape. To copy an extension into your app, take its source from `lib/src/deprecated/deprecated_extensions.dart` of the version you use (the implementations are in `lib/src/util/extension/`). Until 1.0.0 the deprecated extension is still exported, and two extensions with the same members on the same type make every use ambiguous. Either give your copy's members other names, or hide the deprecated one in the files that use your copy:

```dart
import 'package:impaktfull_ui/impaktfull_ui.dart' hide DateTimeExtensions;
import 'package:my_app/util/date_time_extensions.dart';
```

After upgrading to 1.0.0, remove the `hide`.

## Right-to-left layouts

Parameters that only accepted a physical `Alignment` are replaced by an `AlignmentGeometry` parameter, so you can pass an `AlignmentDirectional` that follows the reading direction.

| Class | Deprecated | Replacement |
| --- | --- | --- |
| `ImpaktfullUiScreen` | `fabAlignment` (constructor, getter) | `floatingActionButtonAlignment` |
| `ImpaktfullUiAdaptiveScreen` | `fabAlignment` (constructor, getter) | `floatingActionButtonAlignment` |

`dart fix` renames the constructor argument and keeps its value, so a physical `Alignment` you passed stays where it was. Without an argument the fab is now placed at `AlignmentDirectional.bottomEnd`: the bottom right corner in a left-to-right layout (as before) and the bottom left corner in a right-to-left layout. The deprecated `fabAlignment` getter returns the left-to-right value of `floatingActionButtonAlignment`; replace reads of it by hand, since the new getter is an `AlignmentGeometry`.

## `dart:io` File APIs

A `File` of `dart:io` can not be read on the web, so the APIs that take one are deprecated. Their replacements take bytes (`Uint8List`) or an `XFile` of [`cross_file`](https://pub.dev/packages/cross_file) (which `image_picker` and `file_selector` return) and work on every platform, including the web with JS and Wasm.

| Deprecated | Replacement |
| --- | --- |
| `ImpaktfullUiGalleryItem.file(file: file)` | `ImpaktfullUiGalleryItem.xFile(xFile: XFile(file.path))` or `ImpaktfullUiGalleryItem.bytes(bytes: bytes)` |
| `ImpaktfullUiGalleryItem.file` (field) | `ImpaktfullUiGalleryItem.xFile` or `ImpaktfullUiGalleryItem.bytes` |
| `ImpaktfullUiImageCropController.cropImageFile(cropInfo:, file: file)` | `cropXFile(cropInfo:, xFile: XFile(file.path))` or `cropImageBytes(cropInfo:, bytes: bytes)` |
| `ImpaktfullUiImageCropCropper.cropImage(imageFile: file)` | `cropImage(xFile: XFile(file.path))` or `cropImage(imageBytes: bytes)` |

`dart fix` can not migrate these for you: the replacement takes a different type. Add `cross_file` to your `pubspec.yaml` to create an `XFile` yourself.

Until 1.0.0 the deprecated APIs keep working on Android, iOS, macOS, Windows and Linux. `cropImageFile` now crops the file instead of throwing `imageFile is not supported yet`. On the web they still compile (the parameter accepts any object there), but reading the file throws an `UnsupportedError`.

## Changed behavior

These releases change how a component behaves without changing its API in a breaking way. Check them when you upgrade.

| Component | Before | Now |
| --- | --- | --- |
| `ImpaktfullUiTable` | A row or header without a `columnConfig` used equal columns, even when the table had a `columnConfig`. | A row or header without a `columnConfig` (or with an empty one) uses the `columnConfig` of the table. A `columnConfig` on the row or header still wins. |
| `ImpaktfullUiAutoComplete` | The overlay only closed with escape or the controller. | The overlay also closes on a tap outside the input field and the overlay, and when the focus leaves both (e.g. with tab). |
| `ImpaktfullUiIconButton` | `onTap` could not be `null`. | The `onTap` constructor parameter accepts `null` to disable the button. The `onTap` getter stays a non-nullable `VoidCallback` (a function that does nothing when disabled); use `isEnabled` / `isDisabled` to check. Without a `size` the icon uses `ImpaktfullUiIconButtonTheme.dimens.iconSize` (16 by default, as before). |
| `ImpaktfullUiComponentsTheme` | Had no `iconButton`. | Has an `iconButton` theme. The constructor parameter is optional and defaults to `ImpaktfullUiIconButtonTheme.fallback` (the look from before); it becomes `required` in 1.0.0. |
| `ImpaktfullUiIntroduction` | Rendered an empty `Container`. | Renders its `pages`. Without pages it renders nothing (`SizedBox.shrink`). It is still a `StatelessWidget`. |
| `ImpaktfullUiCarousel` | Changing `index` always animated to it. | Changing `index` to the page that is already shown (e.g. the index of `onItemChanged` passed back) no longer animates, so it does not interrupt the swipe of the user. |
| `ImpaktfullUiNotification.show` | Always used `SnackyController.instance`. | Uses `controller`, else the `snackyController` of the `ImpaktfullUiApp` above `context`, else `SnackyController.instance`. Without `context` and `controller` nothing changes. |
| `ImpaktfullUiSkeleton` | The shimmer was a gradient of the background colour at 20% opacity, drawn on top of that same background, so it was not visible. | The shimmer uses `ImpaktfullUiSkeletonColorTheme.highlight` (`colors.card`, white by default), so it is visible on the background. The focus ring of a component inside a scroller is drawn against the inside
edge of the component instead of around it: a tab of
`ImpaktfullUiHorizontalTabs`, an item of `ImpaktfullUiSidebarNavigation` and a
row of `ImpaktfullUiTable`. The viewport of the scroller clipped the ring that
was drawn around them, so only the parts along the sides were visible. The
color and the thickness are the ones of
`ImpaktfullUiTouchFeedbackTheme.focusRing`, and nothing about the size or the
layout of those components changed. `ImpaktfullUiFocusRingTheme.inset` gives
the same ring for a component of your own inside a scroller.

`ImpaktfullUiDropdown` opens its menu inside the window. It used to open under
its button whatever was there, which cut the menu off at the bottom of the
window, and it gave the menu exactly the width of its button, which left the
items of a narrow button almost no room. The menu now:

- opens **above** the button when there is no room under it;
- **slides** along the edge of the window instead of hanging out of it;
- is **never taller** than the space it has, and its content scrolls;
- is at least `ImpaktfullUiDropdownDimensTheme.minWidth` (176) wide when it
  takes the width of its button. **This is a visible change**: a dropdown with
  a narrow button gets a wider menu than before. `childWidth` still gives the
  menu exactly that width, and `overlayWidth` is still the width of a menu
  whose button has not been measured yet.

`ImpaktfullUiDropdownAlignment` is the corner the menu prefers, not the corner
it is nailed to.

The focus ring of an `ImpaktfullUiInputField` is thinner by the width of its
border, and a field that draws its own ring no longer gets a second one from
its card. The ring is a shadow that spreads out of the box of the card, and
the border of a card is painted inside that box, so adding the border to the
spread made the ring thicker than `focusRingWidth` asked for. A field with a
`focusRing` in its theme (both design system presets have one) showed that
ring *and* the ring of the card around it.

`ImpaktfullUiFocusRingTheme.enabled` turns every focus ring off at once, for
an app that shows the focus in its own way:

```dart
final base = ImpaktfullUiTheme.getDefault();
final theme = base.copyWith(
  components: base.components.copyWith(
    touchFeedback: base.components.touchFeedback.copyWith(
      focusRing: base.components.touchFeedback.focusRing.copyWith(
        enabled: false,
      ),
    ),
  ),
);
```

It takes the focus away from the people who navigate with a keyboard or a
switch, so it is a decision to make on purpose. `ImpaktfullUiCard.useFocusRing`
does the same for one card.

## Base theme tokens reach every component theme

Everything here is additive: a theme that is built the way it was built before
comes out with exactly the same tokens, and no golden changed.

### `ImpaktfullUiComponentsTheme.getDefault`

The block that builds the 87 component themes moved out of
`ImpaktfullUiDefaultTheme.withMinimalChanges` into
`ImpaktfullUiComponentsTheme.getDefault({assets, colors, textStyles, dimens, durations, shadows})`.
`withMinimalChanges` calls it, so nothing changes for a caller; an app can now
build the component themes again itself from changed base tokens.

### `ImpaktfullUiTheme.copyWithBaseTokens`

`ImpaktfullUiTheme.copyWith` keeps its behavior: it replaces exactly the values
it is given, so `copyWith(colors: ...)` leaves `components` alone. The new
`copyWithBaseTokens({label, brightness, assets, colors, textStyles, dimens, durations, shadows, customTheme})`
replaces the base token groups **and** builds every component theme again from
them, so the new token reaches every component. It builds the component themes
from scratch, so it discards a customisation that was applied to a component
theme of that theme: apply those with `copyWith` afterwards.

### New parameters on `withMinimalChanges` and `ImpaktfullUiTheme.custom`

| Parameter | Default | What it does |
| --- | --- | --- |
| `colors`, `textStyles`, `dimens`, `durations`, `shadows`, `assets` | `null` | Replaces that base token group; the component themes are built from the result. `durations` and `shadows` had no parameter at all before, so the animation speed and the shadow scale of the package were unreachable. |
| `radius` | `8` | The seed of the border radius scale (see below). |
| `borderRadiusCircle` | `null` | Was not overridable before. |
| `spacingUnit` | `4` | The unit of the new `ImpaktfullUiSpacingTheme`. |
| `heightDisplay`, `heightText` | `null` | `TextStyle.height` (the line height) of every style of the display / text scale. |
| `letterSpacingDisplay`, `letterSpacingText` | `null` | `TextStyle.letterSpacing` of the same. |
| `fontWeightDisplay`, `fontWeightText` | `null` | `TextStyle.fontWeight` of the same. |

`primary`, `accent` and `secondary` of `withMinimalChanges` and of
`ImpaktfullUiTheme.custom` are optional now, so a theme can be built from a
`colors` group instead. An `assert` keeps them required without one, and they
become `required` again in 1.0.0 when `colors` stays the alternative.

### `ImpaktfullUiTextStylesTheme.getDefault` and the text style builders

`ImpaktfullUiTextStylesTheme.getDefault({colors, fontFamilyDisplay, fontFamilyText, heightDisplay, heightText, letterSpacingDisplay, letterSpacingText, fontWeightDisplay, fontWeightText})`
builds the 13 text style groups from a color theme;
`ImpaktfullUiTextStyleTheme.getByColor` takes the same typography parameters,
and `ImpaktfullUiTextStyleDisplayTheme.getByColor` /
`ImpaktfullUiTextStyleTextTheme.getByColor` take `height`, `letterSpacing` and
`fontWeight`. All of them default to `null`, which is the `TextStyle` without
them: today's typography, unchanged.

### `ImpaktfullUiDimensTheme.getDefault` and the radius seed

`ImpaktfullUiDimensTheme.getDefault({radius, borderRadiusExtraSmall, borderRadiusSmall, borderRadius, borderRadiusLarge, borderRadiusExtraLarge, borderRadiusCircle, spacingUnit, spacing})`
grows the radius scale from one `radius` seed, clamped at 0:
`radius - 4` / `radius - 2` / `radius` / `radius + 4` / `radius + 8`. With the
default seed of 8 that is the 4 / 6 / 8 / 12 / 16 of today. A step that is
passed wins over the seed. The constructor of `ImpaktfullUiDimensTheme` is
unchanged, apart from the new `spacing`.

### `ImpaktfullUiDimensTheme.spacing`

A new `ImpaktfullUiSpacingTheme` (`extraSmall` 4, `small` 8, `medium` 12,
`large` 16, `extraLarge` 24, `extraLarge2` 32, all multiples of one `unit`).
The field is optional with that scale as its default and becomes `required` in
1.0.0. No component reads it yet: their paddings and gaps stay in their own
`*DimensTheme`.

### `ImpaktfullUiDimensTheme.borderRadiusCircle` is `999`, not `99999999`

**Changed default.** The pill radius of the default theme was
`BorderRadius.circular(99999999)`. Flutter clamps a border radius to half the
shortest side when it paints, so both render the same half circle on anything
this package draws, but an `InkWell` with the absurd radius made a software
rendered frame take minutes. It is `BorderRadius.circular(999)` now
(`ImpaktfullUiDimensTheme.borderRadiusCircleMax`). A widget wider than 1998
logical pixels that used `borderRadiusCircle` is the only case that looks
different; pass `borderRadiusCircle` to keep the old value.

### `ImpaktfullUiThemeConfigurator` is exported

The `InheritedWidget` that provides an `ImpaktfullUiTheme` to a subtree is
public, so a theme can be scoped to part of the tree (a preview pane, a
side-by-side comparison, a test) instead of only through
`ImpaktfullUiApp(impaktfullUiTheme:)`.

## Size and state tokens for the button, badge and tab bar

New optional tokens that make a control height, a hover, pressed and disabled
ramp and the tab bar reachable from the theme. **Nothing changes without an
override**: every default is the value the widget hardcoded before, and the
golden images of the components did not move. Like the other new theme fields,
these constructor parameters become `required` in 1.0.0; pass them explicitly
when you build a theme from its constructor instead of with `copyWith`.

### `ImpaktfullUiButtonDimensTheme`

| Token | Type | Default |
| --- | --- | --- |
| `sizes` | `ImpaktfullUiButtonSizesDimensTheme` | The geometry of the five `ImpaktfullUiButtonSize` values |
| `linkPadding` | `EdgeInsetsGeometry` | `EdgeInsets.symmetric(horizontal: 4)` |

`sizes.bySize(size)` is an `ImpaktfullUiButtonSizeDimensTheme` per size:

| Token | Default (extraSmall / small / medium / large / extraLarge) |
| --- | --- |
| `height` | `null` for every size: the height follows from the padding and the line box of the title, like before |
| `padding` | `12/8`, `14/10`, `16/12`, `18/14`, `20/16` (horizontal / vertical) |
| `spacing` | 4 |
| `iconSize` | 20, 20, 20, 20, 24 |
| `loadingSize` | 24, 32, 32, 40, 48 |

A non null `height` makes the button exactly that tall: the content is centred
in it and the **vertical part of `padding` is ignored**. A title that wraps to
more than one line still grows the button instead of overflowing, so `height`
is exact for content that fits and a minimum for content that does not.

`ImpaktfullUiButtonSize.horizontalPadding` and `.verticalPadding` are not
removed, but the button no longer reads them: it reads `padding` of the size,
whose default is the same value. Change the theme, not the enum.

### `ImpaktfullUiButtonColorTheme`

Twelve new tokens of type `ImpaktfullUiButtonStateColorTheme?` (`background`,
`border`, `text`, each `null` = the colour of the normal state), all `null` by
default: `primaryHover`, `primaryPressed`, `primaryDisabled`,
`secondaryHover`, `secondaryPressed`, `secondaryDisabled`, `tertiaryHover`,
`tertiaryPressed`, `tertiaryDisabled`, `destructiveHover`,
`destructivePressed` and `destructiveDisabled`. The button picks them per
`type`, the way it already picks its background: the secondary ones are used by
the secondary, the secondary grey and the destructive secondary button, the
tertiary ones by every button without a background.

With `null` (the default) nothing changes: hover and pressed are the overlay of
`ImpaktfullUiTouchFeedbackTheme` and a disabled button is faded with
`Opacity(0.5)`. A button only tracks the pointer when a hovered or a pressed
colour is set, and a disabled colour replaces the `Opacity`, so the border and
the shadow of a disabled button stay crisp. A raised button
(`config.isRaised`) keeps showing its press with the raised animation and
ignores the pressed colour.

### `ImpaktfullUiBadgeDimensTheme`

| Token | Type | Default |
| --- | --- | --- |
| `sizes` | `ImpaktfullUiBadgeSizesDimensTheme` | The geometry of the three `ImpaktfullUiBadgeSize` values |

`sizes.bySize(size)` is an `ImpaktfullUiBadgeSizeDimensTheme` with
`horizontalPadding` (8 / 10 / 12), `verticalPadding` (2 / 2 / 4),
`paddingOffset` (0 / 1 / 2), `spacing` (4 / 6 / 6) and `widgetSize`
(16 / 18 / 24) for the small, the medium and the large badge: the values that
lived on the `ImpaktfullUiBadgeSize` enum, which an app can not change. The
enum keeps its fields, the badge no longer reads them.

### `ImpaktfullUiTabBarColorTheme` and `ImpaktfullUiTabBarDimensTheme`

Both classes had no fields at all.

## Design system themes

Two themes in the style of a well known design system ship with the package:
`ImpaktfullUiShadcnTheme.light()` / `.dark()` and
`ImpaktfullUiAntDesignTheme.light()` / `.dark()`. They are additive: nothing
changes for a theme that does not use them. See
[doc/design-system-themes.md](design-system-themes.md) for what they cover and
what a theme cannot reach.

### Tokens the design system themes needed

Aligning both presets with their design system took a few more tokens. Every
one of them defaults to what the component did before, so no existing theme
changes.

| Theme | Token | Default |
| --- | --- | --- |
| `ImpaktfullUiNotificationDimensTheme` | `alignment` | `ImpaktfullUiNotificationAlignment.center` (the icon and the actions in the middle, as before). It is the default of the `alignment` parameter of `ImpaktfullUiNotification`, which still wins. Both design systems line the icon up with the first line of the title, which is `top`. |
| `ImpaktfullUiNotificationDimensTheme` | `iconSize` | `null` (the size of the asset, as before). A shadcn/ui alert draws it at `size-4` (16), an Ant Design notification with a description at 24. |
| `ImpaktfullUiRadioButtonColorTheme` | `borderSelected` | `null` (the `border` colour, as before) |
| `ImpaktfullUiNotificationDimensTheme` | `closePadding` / `closeIconSize` | `null` / `null` (the close button is an `ImpaktfullUiIconButton` with the theme of the app, as before). A `size-9` icon button is as tall as a one line alert of a design system, so both presets give the notification a smaller close button. |
| `ImpaktfullUiSegmentedControlDimensTheme` | `activeBorderRadius` | `null` (the `borderRadius` of the track, as before). Both design systems draw the box of the selected item one step smaller than the track (`rounded-md` in a `rounded-lg` list, `borderRadiusSM` in `borderRadius`). |
| `ImpaktfullUiSegmentedControlDimensTheme` | `activeSpacing` / `spacing` | 2 / 4, the values the control hardcoded. Both design systems put the items next to each other (0). |
| `ImpaktfullUiVirtualKeyboardTextStyleTheme` | `text` | The text of the input above the keys. It was taken from the tree around the keyboard, so a `DefaultTextStyle` of the app decided how tall the line was and could push it out of the input. The default theme sets `textStyles.onCard.text.medium`. |
| `ImpaktfullUiVirtualKeyboardDimensTheme` | `inputPadding` | `EdgeInsets.symmetric(horizontal: 16)`. The input used the padding of an `ImpaktfullUiCard` on every side, which left 24 of the 56 for the line of text. |
| `ImpaktfullUiHorizontalTabColorTheme` | `backgroundHoveredTab` | `null` (the overlay of `ImpaktfullUiTouchFeedbackTheme`, as before). `Colors.transparent` shows none: a tab of Ant Design only changes the colour of its title on hover. |
| `ImpaktfullUiHorizontalTabTextStyleTheme` | `hovered` | `null` (`unselected`, as before). The title of an unselected tab while the pointer is over it (`itemHoverColor`). |
| `ImpaktfullUiHorizontalTabColorTheme` | `selectedMarker` | `null` (no bar under the selected tab, as before). The ink bar of Ant Design. |
| `ImpaktfullUiHorizontalTabDimensTheme` | `selectedMarkerHeight` / `selectedMarkerWidth` / `selectedMarkerBorderRadius` | 2 / `null` (the width of the tab) / `null` (square). Only drawn when `selectedMarker` is set. |
| `ImpaktfullUiHorizontalTabsDimensTheme` | `margin` | `EdgeInsets.zero` (the row runs from edge to edge, as before). The space around the row, outside its background, for a design system whose tabs are a track instead of a bar. |
| `ImpaktfullUiHorizontalTabsDimensTheme` | `borderRadius` | `null` (square corners on the background, as before). A shadcn/ui `TabsList` is `rounded-lg`. |
| `ImpaktfullUiSnackyConfiguratorDimensTheme` | `margin` | `EdgeInsets.all(16)`, the margin the snack always had |

### A theme renders its own snack

`ImpaktfullUiSnackyConfiguratorTheme.snackyBuilder` renders a snack the way a
theme wants it:

```dart
// A top level or a static function: a closure written inline is a new object
// on every build, which makes the theme unequal to itself and rebuilds
// everything that reads it.
SnackyBuilder buildSnacky(ImpaktfullUiSnackyConfiguratorTheme theme) =>
    MySnackyBuilder(theme: theme);

final theme = base.copyWith(
  components: base.components.copyWith(
    snackyConfigurator:
        base.components.snackyConfigurator.copyWith(snackyBuilder: buildSnacky),
  ),
);
```

`null` (the default) renders the notification with the tokens of the theme, as
before. A `snackyBuilder` on the `ImpaktfullUiSnackyConfigurator` itself still
wins over the one of the theme.

### `fontSizeText`, the seed of the text scale

`ImpaktfullUiDefaultTheme.withMinimalChanges`,
`ImpaktfullUiTextStylesTheme.getDefault`,
`ImpaktfullUiTextStyleTheme.getByColor` and
`ImpaktfullUiTextStyleTextTheme.getByColor` take the size of body text, which
grows the whole text scale in steps of 2:

| step | value | default (`fontSizeText: 16`) |
|---|---|---|
| `extraLarge` | `fontSizeText + 4` | 20 |
| `large` | `fontSizeText + 2` | 18 |
| `medium` | `fontSizeText` | 16 |
| `small` | `fontSizeText - 2` | 14 |
| `extraSmall` | `fontSizeText - 4` | 12 |

`fontSizeText: 14` is both Ant Design's `fontSize` (with `fontSizeSM: 12` and
`fontSizeLG: 16`) and the `text-sm` of a shadcn/ui control. Without it the
scale is the one of the default theme, so no existing theme changes. The
display scale (72 / 60 / 48 / 30 / 24 / 20) has no seed: pass `textStyles:` or
a `copyWith` per style to change it.


## Planned breaking changes

These are not in place yet. They change behavior, so they wait for 1.0.0.

### `ImpaktfullUiResponsiveLayout` size classes

`ImpaktfullUiResponsiveLayout.build()` and its static helpers (and the `context.is*Screen*` extensions) use the breakpoints differently:

| Size | `build()` builder | Helpers |
|------|-------------------|---------|
| small | `width <= breakpointMedium` (`breakpointSmall` is not used) | `isSmallOrSmaller`: `width <= breakpointSmall` |
| medium | `width <= breakpointLarge` | `isMediumOrSmaller`: `width <= breakpointMedium` |
| large | `width <= breakpointExtraLarge` | `isLargeOrSmaller`: `width <= breakpointLarge` |
| extraLarge | `width > breakpointExtraLarge` | `isExtraLargeOrBigger`: `width >= breakpointLarge` |

So at 800px (default theme) `build()` uses the `small` builder while `isSmallOrSmaller` is false. `isLargeOrSmaller` and `isExtraLargeOrBigger` are also both true at exactly `breakpointLarge`. 1.0.0 will make `build()` and the helpers use the same size classes. Check the layouts that depend on either of them when you upgrade.
